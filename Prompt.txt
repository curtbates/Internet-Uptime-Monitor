Create an Internet Uptime Monitor application in Python. The goal is to monitor an ISP by periodically querying DNS servers and tracking public IP changes. All code must run on both Windows and Linux.

---

PROJECT STRUCTURE

    main.py                  — entry point (terminal)
    main.pyw                 — entry point (no console window; errors via messagebox)
    config_manager.py        — load/save config.json
    database.py              — SQLite helpers
    dns_checker.py           — DNS query logic
    ip_tracker.py            — public IP / ISP lookup
    gui/__init__.py          — empty
    gui/main_window.py       — main window, monitoring loop, tray
    gui/graph_panel.py       — matplotlib graph widget
    gui/setup_dialog.py      — modal setup dialog

main.pyw is identical to main.py in behaviour. On Windows, pythonw (invoked
automatically for .pyw files) runs without a console window. If a required
package is missing it shows a tkinter messagebox instead of a console traceback.

---

DEPENDENCIES

    dnspython      — DNS queries
    requests       — IP lookup HTTP calls
    matplotlib     — embedded graph
    pystray        — system tray (optional, graceful degradation if missing)
    Pillow         — tray icon image (optional, same as pystray)

CONFIG (config.json, stored next to the scripts)

Defaults if file is missing or corrupt:
    polling_interval_seconds: 60
    log_dns: true
    log_only_incomplete_dns: true
    log_score: true
    log_score_below_80_only: false
    save_event_log: false
    log_ip_success: true
    log_isp_changes: true
    dns_providers: [
        {"name": "Google",     "server": "8.8.8.8"},
        {"name": "Cloudflare", "server": "1.1.1.1"},
        {"name": "OpenDNS",    "server": "208.67.222.222"},
        {"name": "Quad9",      "server": "9.9.9.9"},
        {"name": "Comodo",     "server": "8.26.56.26"}
    ]
    domains: ["google.com", "amazon.com", "cloudflare.com", "microsoft.com", "github.com"]

log_dns (bool, default true):
    When true, DNS poll summary lines are written to the Event Log.
    When false, all DNS poll messages are suppressed regardless of
    log_only_incomplete_dns.

log_only_incomplete_dns (bool, default true):
    Effective only when log_dns is true.
    When true, the per-poll DNS summary line is written to the Event Log only when
    at least one query failed (ok_count < total). When false, the summary line is
    written after every poll regardless of outcome.

log_score (bool, default true):
    When true, the computed summary score (0–100) is written to the Event Log after
    each poll, colour-coded with the "ok" tag (green) when score >= 80, the "fail"
    tag (red) when score < 50, and no tag otherwise.

log_score_below_80_only (bool, default false):
    Effective only when log_score is true.
    When true, score messages are suppressed unless the score is below 80.

save_event_log (bool, default false):
    When true, every message passed to _log_event() is appended to event.log in the
    app data directory (same folder as uptime_monitor.db). When the user saves the
    dialog with this value false, delete event.log if it exists.

    Event log file path:
        Windows   %APPDATA%\InternetUptimeMonitor\event.log
        Linux     ~/.InternetUptimeMonitor/event.log

    Use open(APP_DIR / "event.log", "a", encoding="utf-8") and silently swallow
    OSError so a permissions problem cannot crash the app.

log_ip_success (bool, default true):
    When true, IP address change and detection messages are written to the Event Log.
    When false, only the IP check failure message is logged. The database inserts
    (insert_ip_log, insert_ip_failure) and _last_ip / _last_ipv6 state updates are
    unaffected by this setting.

log_isp_changes (bool, default true):
    When true, a dedicated "ISP changed from X to Y" message (with "info" tag) is
    written to the Event Log whenever the detected ISP name differs from the
    previously recorded ISP name on an IPv4 change event. When false, ISP transitions
    are still recorded in the database (via insert_ip_log) but no extra event log
    message is generated. The _last_isp state update is unaffected by this setting.

DATABASE

Store the database in a platform-specific application data directory so it is
never inside a cloud-sync folder (Google Drive, OneDrive, etc.):
    Windows   %APPDATA%\InternetUptimeMonitor\uptime_monitor.db
    Linux     ~/.InternetUptimeMonitor/uptime_monitor.db

Create the directory with parents=True, exist_ok=True on module import using
pathlib and os.environ.get("APPDATA", Path.home()). Expose the directory as the
module-level constant APP_DIR (no leading underscore) so other modules can import
it to locate sibling files such as event.log.

Table dns_results:
    id               INTEGER PRIMARY KEY AUTOINCREMENT
    timestamp        REAL NOT NULL          -- Unix epoch float
    dns_provider     TEXT NOT NULL
    domain           TEXT NOT NULL
    response_time_ms REAL                   -- NULL on failure
    success          INTEGER NOT NULL       -- 1 or 0

Table ip_log:
    id          INTEGER PRIMARY KEY AUTOINCREMENT
    timestamp   REAL NOT NULL
    public_ip   TEXT NOT NULL              -- dotted-decimal IPv4
    isp_name    TEXT
    org         TEXT                       -- raw "AS12345 ISP Name" string
    public_ipv6 TEXT                       -- IPv6 address; NULL when not available

Table ip_failures:
    id        INTEGER PRIMARY KEY AUTOINCREMENT
    timestamp REAL NOT NULL               -- when the failure was first detected

One ip_failures row is written each time a working IP check transitions to
failure (i.e. the first poll that returns None after a successful poll).
Back-to-back failures within the same outage do not add additional rows.

Index timestamp on all three tables. Purge records older than 10 days across
all three tables; run purge once at startup and re-schedule every 24 hours.

Schema migration: initialize_db() must handle databases created before
public_ipv6 was added. After the CREATE TABLE IF NOT EXISTS block, check
PRAGMA table_info(ip_log); if public_ipv6 is absent, run:
    ALTER TABLE ip_log ADD COLUMN public_ipv6 TEXT

DNS CHECKER (dns_checker.py)

Function: check_dns(server_ip, domain, timeout=5.0) -> (bool, float | None)

Use dnspython with configure=False (ignore system resolver). Set both lifetime
and timeout to the timeout value to disable implicit retries. Query an A record.
Measure elapsed time with time.perf_counter(). Return (True, elapsed_ms) on
success or (False, None) on any exception.

IP TRACKER (ip_tracker.py)

IPv4 fetch
----------
Function: get_public_ip_info(timeout=10) -> dict | None
Returns {"ip": str, "ipv6": str | None, "isp": str, "org": str} or None if all
services fail.

On dual-stack hosts, requests may connect to ipinfo.io over IPv6, causing the
service to echo back the IPv6 address as "ip" rather than the IPv4 address.
Prevent this with a custom HTTPAdapter subclass (_ForceIPv4Adapter) that
temporarily sets urllib3.util.connection.allowed_gai_family to return
socket.AF_INET for the duration of every send() call, then restores the
original. Mount this adapter on a module-level requests.Session (_ipv4_session)
for both "https://" and "http://", and use _ipv4_session.get() for all IPv4
service calls.

Try these services in order via _ipv4_session, falling through on any exception:
  1. https://ipinfo.io/json            — JSON; ip field = "ip", org field = "org"
  2. https://ipapi.co/json/            — JSON; ip field = "ip", org field = "org" or "isp"
  3. https://api.ipify.org?format=json — JSON; ip field = "ip", no org field
  4. https://checkip.amazonaws.com     — plain text; entire response body is the IP

For each service, attempt resp.json() first to extract ip and org/isp. Catch
ValueError (plain text response) and fall back to resp.text.strip() as the IP
with data = {}.

After extracting the IP, check for ISP data:
    org = data.get("org", "") or data.get("isp", "") or ""

If org is empty (services 3 and 4 never provide one; services 1 or 2 may omit
it under rate limiting), save the IP as fallback_ip (only the first such IP
is kept) and continue to the next service. Do NOT return "Unknown" immediately.

If org is non-empty, strip the leading ASN token (e.g. "AS7922 Comcast...") and
use the remainder as the displayed ISP name; store the raw org string separately.
Return immediately with this result.

After the loop:
  - If any service returned both IP and org, it was already returned above.
  - If at least one service returned an IP but none provided org data, return
    {"ip": fallback_ip, "ipv6": ..., "isp": "Unknown", "org": ""}.
  - Only return None when every service failed to return any usable IP.

IPv6 fetch
----------
Function: _fetch_ipv6(timeout=5) -> str | None

Use plain requests.get() (not _ipv4_session) to hit:
    https://api6.ipify.org?format=json
This endpoint has only AAAA DNS records, so the OS must use IPv6 to reach it.
Return the "ip" field from the JSON response, or None on any exception
(including connection failure, which simply means the host has no IPv6).

Call _fetch_ipv6() inside get_public_ip_info() after a successful IPv4 response
and include the result as "ipv6" in the returned dict.

MAIN WINDOW (gui/main_window.py)

Window title: "Internet Uptime Monitor - by Curt Bates - v20260626a"
Initial size: 1050x720, minimum: 800x580

Layout (top to bottom, using pack):
  1. Menu bar
  2. Status bar (sunken frame)
  3. Content area (graph panel above, event log below) — fills remaining space
  4. Bottom bar

MENU BAR

  Left to right, separated by vertical separators:

  Right-aligned:

Pre-populate IP/ISP on startup from the most recent ip_log record (so the user
sees the last-known IP immediately without waiting for the first poll). Also
seed _last_ipv6 from the same record's public_ipv6 field.

CONTENT AREA
  Top portion: GraphPanel widget (fills remaining space, expandable)
  Bottom portion: LabelFrame "Event Log" containing a read-only Text widget,
    6 rows tall, Courier New 9pt, word-wrap, with a vertical scrollbar.
    Auto-scroll to the newest entry after each insert.
    Named colour tags:
      "ok"   → #27ae60 (green)  — all DNS lookups succeeded
      "fail" → #c0392b (red)    — all DNS lookups failed

_log_event(msg, tag):
  Inserts "[YYYY-MM-DD HH:MM:SS] msg\n" into the Text widget with the given tag.
  If config.get("save_event_log", False) is true, also appends the same line
  to APP_DIR / "event.log" (open in "a", encoding="utf-8"). Silently swallow
  OSError so a file-system problem cannot crash the app.

_open_setup (Setup > Configure… handler):
  After the user saves the dialog, if config.get("save_event_log", False) is
  false, delete APP_DIR / "event.log" if it exists (Path.unlink()).

BOTTOM BAR
  "▶  Start Monitoring" / "■  Stop Monitoring" toggle button (left)
  "Interval: N s" label in gray (left, next to button)

MONITORING LOOP
  - Use root.after() to schedule polls; run actual DNS + IP work in a daemon thread.
  - Use a queue.Queue to pass results from the worker thread back to the main thread.
  - Drain the queue every 200 ms with root.after(200, _queue_check).
  - Track _last_ip (IPv4), _last_ipv6, and _last_isp separately in MainWindow.__init__.
    Pre-populate all three from the most recent ip_log record on startup.
  - On each completed poll cycle:
      • Write all DNS results to the database.
      • If ip_info is not None:
          - ip_changed   = ip != _last_ip
          - ipv6_changed = ipv6 is not None and ipv6 != _last_ipv6
            (treat a None IPv6 result as a transient fetch failure, not a change,
             to avoid spurious "lost IPv6" events)
          - If ip_changed OR ipv6_changed: insert one ip_log row with current
            IPv4, IPv6, ISP.
          - If ip_changed:
              • If _last_isp is not None and isp != _last_isp and log_isp_changes:
                log "ISP changed from <_last_isp> to <isp>" with "info" tag.
              • Update _last_isp = isp always (regardless of logging flag).
              • If log_ip_success, log "Public IP changed to / detected as X  (ISP)"
                with "info" tag.
              • Update _last_ip always (regardless of logging flag).
          - If ipv6_changed and NOT ip_changed: if log_ip_success, log "Public IP: X  (ISP)"
            with "info" tag (current IPv4 for context alongside the IPv6 event).
          - If ipv6_changed: if log_ip_success, log "Public IPv6 changed to / detected as X  (ISP)"
            with "info" tag; update _last_ipv6 always (regardless of logging flag).
            (log_ip_success  = config.get("log_ip_success", True))
            (log_isp_changes = config.get("log_isp_changes", True))
      • If ip_info is None and _last_ip is not None: log the failure once with
        "fail" tag; call insert_ip_failure(ts) to persist the event; reset both
        _last_ip and _last_ipv6 to None so the next successful poll re-logs
        both addresses even if unchanged.
      • Compute the summary score (see Score Formula below) and store as _last_score.
      • Log a DNS poll summary line: "DNS poll: N/T succeeded[, avg X.X ms]"
        with ok/fail/no-tag colouring as described above, but only when
        log_dns is true AND (log_only_incomplete_dns is false OR ok_count < total).
        (log_dns = config.get("log_dns", True))
        (log_only_incomplete_dns = config.get("log_only_incomplete_dns", True))
      • If log_score is true and (log_score_below_80_only is false OR score < 80):
        log "Score: X.X/100" with "ok" tag when score >= 80, "fail" tag when
        score < 50, no tag otherwise.
        (log_score = config.get("log_score", True))
        (log_score_below_80_only = config.get("log_score_below_80_only", False))
      • Update "Last check" and "Next" labels in the status bar.
      • Refresh the graph panel.
      • Update the tray icon.
      • Schedule the next poll using the configured interval.
  - Start monitoring automatically when the application launches.

SCORE FORMULA (used both in the live poll handler and the graph panel)
  success_rate = successful_lookups / total_lookups   (0.0–1.0)
  rt_score     = clamp(1.0 - (avg_response_time_ms - 20) / 480, 0.0, 1.0)
                 (20 ms → 1.0,  500 ms → 0.0)
  score        = min(100.0, (success_rate * 0.5 + rt_score * 0.5) * 100)

EXPORT LOG (File > Export to Log File…)
  Ask for a save path (default filename: uptime_log_YYYYMMDD_HHMMSS.txt).
  Write a header (title + generated timestamp), then three sections:

  Section 1 — DNS FAILURES
    The subset of dns_results rows where success = 0. Columns: timestamp,
    provider, domain, IPv4, IPv6, ISP. Response time and OK? are omitted.

  Section 2 — IP CHECK FAILURES
    Every ip_failures row. Single column: Timestamp.

  Section 3 — DNS RESULTS
    Every dns_results row. Columns: timestamp, provider, domain, response time,
    success flag ("yes"/"no"), IPv4, IPv6, ISP. Determine the active IP/ISP by
    walking the ip_log rows (sorted ascending) and finding the last transition
    whose timestamp <= the DNS row's timestamp.

  For all sections: format timestamps as "YYYY-MM-DD HH:MM:SS"; show "—" for
  missing IPv6 or unknown fields; write "  (no records)" when a section is empty.

  Column order and widths for DNS RESULTS / DNS FAILURES:
    Timestamp  22  Provider  10  Domain  22  [RT(ms)  8 right  OK?  3 — RESULTS only]
    IPv4  17  IPv6  39  ISP  (no fixed width, last column)

GRAPH PANEL (gui/graph_panel.py)

Embed a matplotlib Figure (9×4 inches, 100 dpi) with a NavigationToolbar2Tk below it.
Use the TkAgg backend. Use tight_layout() and autofmt_xdate(rotation=30) after each draw.

CONTROLS ROW (above the graph):
  "View:" label + radio buttons: By Provider | By Domain | Summary Score
  Vertical separator
  "Range:" label + readonly Combobox: Last 1h | Last 6h | Last 24h | Last 7d
  "Refresh" button
  Vertical separator
  "ISP:" label + readonly Combobox (populated from distinct ISP names in ip_log,
    plus "All ISPs" as the first option); filters results to only records that
    occurred while the selected ISP was active (determined by walking ip_log
    transitions backward)

TIME RANGES AND BUCKET SIZES:
  Last 1h  →  60 s buckets  (up to 60 data points)
  Last 6h  → 300 s buckets  (up to 72 data points)
  Last 24h → 900 s buckets  (up to 96 data points)
  Last 7d  → 3600 s buckets (up to 168 data points)

Bucket a timestamp: int(timestamp / bucket_s) * bucket_s  (floor to bucket boundary)

BY PROVIDER VIEW
  One line per DNS provider. For each time bucket, average the response times of
  all successful queries for that provider. Plot with marker="o", markersize=3.
  Title: "DNS Response Time by Provider"
  Y-axis: "Avg Response Time (ms)"

BY DOMAIN VIEW
  Same as By Provider but keyed on domain name.
  Title: "DNS Response Time by Domain"
  Y-axis: "Avg Response Time (ms)"

SUMMARY SCORE VIEW
  For each time bucket combine all providers and domains:
    - Track success count and total count (from all records including failures)
    - Track response times (from successful records only)
    - Compute score using the Score Formula above
  Plot a single steelblue line with shaded fill_between (alpha=0.25).
  Add dashed reference lines: orange at 80 ("Good (80)"), red at 50 ("Poor (50)").
  Title: "Summary Score  (50 % success rate + 50 % response time)"
  Y-axis: "Score (0 – 100)", ylim (0, 105) for visual headroom above 100.

Refresh the graph after every completed poll and whenever the user changes the
view, time range, or ISP filter. Show a "No data available" placeholder when
there are no results for the selected range.

SETUP DIALOG (gui/setup_dialog.py)

Modal Toplevel, 520×460, not resizable. Four-tab Notebook:

Tab 1 — DNS Providers
  Listbox showing "Name  (server_ip)" for each provider, with vertical scrollbar.
  Clicking a row copies it into the Name / Server IP entry fields below.
  Buttons: Add (appends new entry), Update (overwrites selected entry), Remove.

Tab 2 — Domains
  Listbox of domain names. Entry field with Add (on button click or Enter key)
  and Remove buttons. Normalise domains to lowercase; silently ignore duplicates.

Tab 3 — Settings
  Spinbox for polling interval (10–3600 seconds).

Tab 4 — Event Log
  Checkboxes (top to bottom); indented sub-checkboxes are disabled when their
  parent is unchecked:

  1. "Log DNS responses to event window" (default: checked)
     Controls config key log_dns.
     Checked:   DNS poll summary lines are written to the Event Log.
     Unchecked: all DNS poll messages are suppressed.

     1a. "Only log incomplete DNS responses" (sub, indented, default: checked)
         Controls config key log_only_incomplete_dns.
         Checked:   the DNS summary line is suppressed when all queries succeed.
         Unchecked: the DNS summary line is written after every poll.

  2. "Log IP successful detection messages" (default: checked)
     Controls config key log_ip_success.
     Checked:   IP address change and detection messages appear in the Event Log.
     Unchecked: only IP check failure messages are logged; state tracking (_last_ip,
                _last_ipv6) and database inserts are unaffected.

  3. "Log ISP changes to event window" (default: checked)
     Controls config key log_isp_changes.
     Checked:   when the ISP name changes alongside an IPv4 address change, a
                dedicated "ISP changed from X to Y" message is written to the
                Event Log with the "info" tag.
     Unchecked: ISP transitions are still recorded in the database but no extra
                event log message is generated. The _last_isp state update is
                unaffected.

  4. "Log score to event window" (default: checked)
     Controls config key log_score.
     Checked:   the summary score (0–100) is written to the Event Log after each poll.
     Unchecked: no score messages are written.

     4a. "Only log scores below 80" (sub, indented, default: unchecked)
         Controls config key log_score_below_80_only.
         Checked:   score messages are suppressed unless the score is below 80.
         Unchecked: every score is logged.

  5. "Save Event Log" (default: unchecked)
     Controls config key save_event_log.
     Checked:   every _log_event message is appended to event.log in APP_DIR.
     Unchecked: no file is written; the file is deleted on Save if it exists.

Save button validates: interval in range, at least one provider, at least one domain.
Cancel discards all changes. self.result is None on cancel, updated config dict on save.
The dialog deep-copies all config keys on open so edits don't affect the live config
until the user clicks Save. Sub-checkboxes use a command= callback on their parent to
toggle their tk.DISABLED / tk.NORMAL state immediately when the parent is clicked.

SYSTEM TRAY (optional, requires pystray + Pillow)

If pystray/Pillow are not installed, the app still runs; closing just quits instead
of minimising to tray.

Minimising the window (Unmap event) or clicking the window's X button hides the
window (root.withdraw()) and creates a tray icon. A 150 ms delay before hiding
prevents a visual glitch on some platforms.

Tray icon: 64×64 RGBA filled circle with white outline (3 px).
  Blue  (#2980b9) — not monitoring
  Green (#27ae60) — monitoring, score > 80 or score not yet available
  Yellow (#f39c12) — monitoring, score 50–80
  Red   (#c0392b) — monitoring, score < 50

Tray tooltip: "Internet Uptime Monitor  [Monitoring/Stopped]  Last check: HH:MM:SS"

Tray menu:
  Show          (default action, also triggered by double-click)
  ─────
  Start/Stop Monitoring   (label reflects current state dynamically)
  ─────
  Exit

Restoring from tray: stop the pystray icon, call root.deiconify() / lift() /
focus_force(). All pystray callbacks must marshal to the main thread via
root.after(0, ...) because pystray runs on its own thread.
